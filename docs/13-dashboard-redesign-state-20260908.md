# CRE 대시보드 개편 상태 — 2026-09-08

이 문서는 현재 작업의 검증 기록이다. 아래 `진행 중` 항목은 배포·정상 동작 완료를 의미하지 않는다. 설계 근거는 [개편 계획](12-dashboard-redesign-plan-20260908.md)을 참고한다.

## 권위와 연결

- 원본: `data/market.db` — 수집 원문, 버전, 분류, 근거와 이력을 보존하는 로컬 SQLite.
- 기존 온라인 가공본: `data/market-serving-v2.candidate.db` — 원본과 별개인 compact serving 후보. 이번 검증본은 `data/market-serving-redesign-20260908.candidate.db`로 별도 생성한다.
- 온라인: Vercel Next.js → 승인목록 확인 → Turso serving 조회. 원본 전체 이력의 반복 조회는 기사·거래용 projection으로 대체한다.
- Turso는 9월 월간 읽기 한도가 초과됐다. 사용자는 무료 유지와 다른 DB 별도 검토를 선택했다. `2026-10-01` 전에는 예약 작업에서 원격 접속·발행을 시도하지 않는다. 저장용량 부족과 구분한다.
- 온라인 로그인과 실제 데이터 조회 QA는 읽기 제한 해제 및 첫 migration/publication 후 통과해야 한다. 로컬 SQLite QA 성공만으로 온라인 정상화를 주장하지 않는다.

## 화면과 의미

- 메인 목적을 최신기사 / 시계열자료 두 개로 통합한다. 기존 기업·기관·후보 원천을 삭제하지 않는다.
- 최신기사는 제목 중심의 compact 목록, 대표 주제 필터, 현재 불러온 기사 내 검색, 날짜 선택으로 구성한다.
- 자동 분류는 검토 전 상태를 표시한다. 수집 검색어를 기사 주제나 확정 사건으로 간주하지 않는다. 기사 한 건의 대표 주제는 하나이며 필터 숫자는 실제 목록과 일치시킨다.
- 본문 요약이 없으면 없다고 표시하고 원문으로 연결한다. 제목 복제나 raw JSON을 요약으로 보여주지 않는다.
- 시계열은 서울 비주거 신고거래 / 금리·거시 / 서울 건축인허가로 구분한다. 기준월·출처·범위·단위·부분월·결측을 함께 표시한다.
- 거래 건수는 자산 수가 아니다. 최근월 신고 지연을 시장 위축으로 단정하지 않는다.

## 정합성 조정

- 기사별 최신 버전·유효 CRE 범위·관리형 분류를 오프라인에서 계산하고 날짜 인덱스가 있는 serving table로 제공한다.
- 인허가는 최신 **완료** snapshot을 사용한다. 부분 수집이나 실패가 직전 정상 집계를 덮어쓰지 않는다. 비정상 날짜·면적은 품질 항목으로 분리한다.
- MOLIT 과거 수집은 `run_documents` 이력이 축약된 구간이 있다. 전체 응답임이 확인된 구·월 partition만 권위 snapshot으로 교체한다. baseline 없는 불완전 partition은 0건으로 표시하거나 월 합계에 섞지 않는다. 비교월이 없으면 증감률도 제공하지 않는다.
- 원격 발행은 대상 serving table과 검증된 row fingerprint에 제한한다. 원천·권한 테이블을 삭제하지 않는다. 정상 데이터와 freshness metadata를 같은 발행 단위로 다룬다.

## 자동화

Windows 작업은 동일한 단일 실행기와 lock을 사용한다. PC가 켜져 있고 해당 Windows 사용자가 로그인한 상태가 전제다. 종료·로그아웃 중 실행을 보장하는 클라우드 수집기는 아니다.

| 자료 | 한국시간 주기 | 범위 및 실패 처리 |
|---|---|---|
| 최신기사 | 매일 06·09·12·15·18·21시 | 최근 2일 재조회, slot 중복 방지, 분류 후 검증 |
| 금리·거시 | 평일 08시 | 공표/정정 관측 반영, 미국 국채 최근 연도, 기존 역사 보존 |
| 서울 비주거 거래 | 수요일 07:30 | 최근 3개월 재조회, 후행 신고·정정·취소 반영 |

원격은 읽기 제한 해제 이후 additive serving migration을 먼저 적용하고 변경 행만 발행한다. 제한이 계속되면 오류를 기록하며 요금제 변경이나 다른 DB 이동을 자동 실행하지 않는다.

## 배포 및 보안 경계

- 작업 폴더는 Org_dashboard 저장소에 속하지만, 실제 Vercel 프로젝트는 Crus7230/CRE-DB의 main과 연결돼 있으며 소스 루트는 web이다. 서로 다른 저장소임을 확인하고 각 최신 main 기반의 분리 작업 브랜치를 사용한다. 기존 작업 폴더의 다른 변경은 되돌리지 않는다.
- 현재 승인 이메일 입력 방식은 메일함 소유를 인증하지 않는다. 승인 주소를 아는 사람이 입력할 수 있는 MVP이며 OTP/SSO와 동등한 보안을 제공하지 않는다. 민감한 자료를 공개 인터넷에서 제공하려면 별도 본인 인증 또는 접근 보호가 필요하다. 이번 작업에서 기존 인증을 우회하거나 완화하지 않았다.
- Turso quota 해제와 최초 migration/publication, 실제 온라인 로그인·데이터 검증은 아직 남아 있다. 공개 로그인 화면이나 로컬 테스트 통과를 이 검증의 대체로 간주하지 않는다.
