# 로컬 스마트 조회 및 데이터 분리 — 2026-09-08

## 반영 범위

로컬 대시보드의 탭은 `최신기사 / 시계열자료 / 스마트 조회`다. 온라인 배포, 원격 DB 변경, Git push는 이번 작업 범위가 아니다.

스마트 조회는 입력만으로 외부 API를 호출하지 않는다. 조회 버튼이나 Enter를 누르면 주소/회사/종목코드를 보수적으로 판별하고, 정확한 후보를 선택한 뒤 상세 API를 호출한다. 모호한 이름은 주소와 기업 후보를 같이 확인한다.

- 주소: VWorld의 도로명·지번 → PNU 확인 → 국토부 건축HUB 표제부·총괄표제부. 각 동의 연면적·층수·용도·사용승인일을 먼저 보여주고 대장 코드·주소 상세는 접는다. 같은 필지의 다른 동을 한 건물로 합치지 않는다.
- 기업: OpenDART 고유번호 목록 → 기업개황·최근 1년 공시 최대 10건 → 시장 구분에 맞는 KRX 종목 기본정보. 공시는 시간순으로 해당 원문에 직접 연결한다. 실시간 주가/전 재무제표 조회 기능은 아니다.
- 원천별 오류·승인 필요·시간 초과를 자료 없음과 구분한다. 원천 숫자 0을 임의로 결측으로 바꾸지 않는다. 공개 건축물 항목만 조회하며 소유자 개인정보는 조회하지 않는다.
- 정상 결과 5분 캐시, 회사목록 6시간 캐시, 원천별 15초/전체 원천 요청 35초 제한. 입력·후보는 서버 검증한다. 인증키는 외부 env 또는 서버 런타임에서만 읽고 클라이언트·보고서에 포함하지 않는다.

## 분리 결과와 의미

공공 API 게이트웨이의 HTTP 502/503/504는 같은 요청 시간 제한 안에서 250ms 후 1회만 재시도한다. 인증/권한/쿼터(401/403/429) 오류는 재시도하지 않는다. 1회 재시도 후에도 실패하면 부분 결과 또는 원천 오류를 표시한다.

`data/split/manifest.json`은 검증이 완료된 불변 snapshot을 가리킨다.

| 파일 | 크기 | 주 데이터 |
| --- | ---: | --- |
| news.db | 10,813,440 bytes | 날짜 497, 기사 2,129, 분류행 1,085, 기사상세 2,129 |
| timeseries.db | 155,271,168 bytes | 거래 current 17,964, 월간 금융값 4,471, 금리 series 19, 인허가 월간행 94,716 |

크기는 원천 전체가 아닌 **현재 대시보드 조회용 projection** 기준이다. 원본 `data/market.db`(1,712,631,808 bytes)는 삭제하거나 변경하지 않았다. 원천 문서·수집이력·분류·관계 스키마를 공유하므로 원본 전체를 단순히 두 파일로 자르는 것은 안전하지 않다. 현재 두 화면은 독립된 파일로 조회할 수 있도록 분리했다. FK 부모 코드 테이블은 필요한 쪽에 포함했다. 원본의 미사용 인허가 hot detail과 기타 이력은 보존했다.

두 출력은 같은 읽기 전용 transaction에서 복제하고 table별 건수·내용 SHA-256·schema hash 일치, foreign_key_check 0건, integrity_check=ok, runtime SQL smoke를 검증했다. 상세 수치는 snapshot의 `snapshot-manifest.json`에 있다.

로그인에는 작은 `data/local-access.db`를 사용한다. 기존 승인된 3명의 subject ID·이메일·승인상태를 복사했으며 새 사용자를 추가하지 않았다. 기사/시계열 DB에는 로그인 쓰기가 발생하지 않는다. 기존 이메일 입력 방식은 이메일 소유권 인증이 아니므로 외부 공개 전 OTP/SSO 재설계가 필요하다.

## 실행과 갱신

프로젝트 `web` 폴더에서:

```powershell
npm run build
node scripts/start-local-split.mjs
```

서버는 `127.0.0.1:3005`에만 바인딩된다. 중앙 키 파일 기본 경로는 `C:/10137_WorkSpace/env/.env`이며 필요시 `SMART_LOOKUP_ENV_FILE`로 지정한다. 서버를 재시작하면 별도 영구 secret이 없는 경우 다시 로그인해야 한다.

원본 수집/serving 갱신을 마친 뒤 프로젝트 루트에서:

```powershell
python scripts/split_local_serving_databases.py --source data/market.db --output-dir data/split --apply
```

완료 후 로컬 서버를 재시작하면 새 manifest의 두 파일을 사용한다. 실행 중에는 시작 시점의 동일 snapshot으로 고정된다. 이번 작업은 원본 수집 예약을 바꾸지 않았으며, **분리 snapshot 자동 재생성·서버 자동 재시작은 아직 연결하지 않았다.** 원본만 갱신하면 실행 중 대시보드 자료는 자동으로 바뀌지 않는다. 이를 숨겨 실시간 DB 연결로 표현하지 않는다.

최초 `local-access.db`가 없는 환경만 `--seed-auth-db`에 기존 승인목록 DB를 명시해야 한다. 기존 파일을 덮어쓰거나 승인목록을 자동 재설정하지 않는다.
